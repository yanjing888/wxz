# 实验过程考核

学生在实验台完成操作后，上传图片，按需填写实验数据表格，点击“完成本步并提交检查”。普通步骤提交成功后立即解锁下一步，教师异步检查和评分。退回时必须填写意见；学生可以继续已解锁的步骤，并返回被退回步骤补交图片和数据、申请复查。仅显式配置为关键检查点的步骤需要教师通过后放行。教师不能评分尚未提交完整材料的步骤。

全部步骤提交完整证据、关键检查点通过后即可结束实验、撰写报告，无需等待普通步骤全部评分。结束后，教师仍可评价待检查记录，学生仍可补充待检查材料或提交整改；已通过的步骤只读。切换步骤、提交数据、问答携带的步骤编号和结束实验都有后端校验，不能跳过尚未提交的步骤。旧的进行中会话若停在尚未解锁的步骤，学生页面会返回当前待完成步骤；已结束且从未提交的历史步骤保留查看，不自动补分或创建证据。

过程记录按学生、实验和步骤保存，关联提交时的会话；新建对话会保留过程成绩并回到待完成步骤。每次提交保存当时的数据、当次检查图片、说明、教师评分和检查历史，删除原数据不会移除已保存的证据快照。重复提交相同内容不会重复申请，补充图片或说明会单独留痕；已通过的步骤不能重复打分。教师只能检查自己有权限管理的班级，过期的评分页面会拒绝覆盖更新后的记录。

学生在“步骤检查”中直接上传或拍摄检查图片，随完成申请一起保存。图片必填，至少一张、数量不设上限，按实际提交数量展示；只接受考核入口提交的图片，不引用旧对话图片。单张不超过 10MB，每次上传合计不超过 18MB；支持 JPG、PNG、WebP、GIF、BMP。选择中的图片仅在浏览器预览，提交成功才写入数据库。等待检查时可以补充图片、表格和说明，材料会更新版本并留存历史；整改后重新提交需要新图片，原图仍保留在旧记录中。

实验数据表格选填，不提交表格也可完成本步，点击“插入表格”通过网格或行列数选择创建，支持 2–50 行（含表头）、1–20 列，单元格最多 2000 字。如提交表格，第一行为表头，各列表头不能为空，表头之外至少填写一项实际数据。支持增行增列和放大填写，切换步骤保留未提交的表格和图片草稿；失败可重试。表格与图片在同一次请求中保存为证据快照，教师端当前材料和历史记录均可放大查看。

教师页面沿用系统的列表、分栏和表单样式，默认展开待检查学生，按学生查看全部步骤。提交材料与检查历史分别显示；图片支持缩略图和原图预览。空地址会被过滤，缺失文件会明确提示，不生成替代图片。后台轮询在没有评分草稿时更新材料；有未保存的评分时保留草稿，提示材料更新，避免覆盖教师输入。

## 评分设置

过程考核由教师为每个实验选择“本次教学班”，一次展示一个班级。未选择或清空选择时，过程考核列表为空；选择按教师与实验保存，切换实验后各自保留。候选班级只包含已分配当前实验且教师有权限管理的班级，以实验分配时的教学班为准，不因学生加入其他班级而扩展。重新进入过程考核时刷新候选班级；取消分配后不再展示该班，旧选择也失效。接口同时校验所选班级，避免跨班混入。

该选择只影响过程考核。学情分析、报告批阅和反馈仍按所选实验展示原有数据，学习统计保留原来的班级筛选。

实验的 `manifest.json` 支持以下字段，修改后重启后端：

```json
{
  "processScoreWeight": 40,
  "steps": {
    "1": {
      "title": "仪器准备",
        "assessmentRequired": true,
        "assessmentBlocking": false,
      "assessmentMaxScore": 20,
      "assessmentCriteria": ["装置摆放稳定", "光路调整正确"]
    }
  }
}
```

- `assessmentRequired`：默认 `true`，决定是否由教师评分；为 `false` 时提交完整证据后完成，不计教师过程分。
- `assessmentBlocking`：默认 `false`，提交后即可继续；为 `true` 且需要教师评分时，教师通过后才解锁下一步。牛顿环当前所有步骤均为提交即放行。
- `assessmentMaxScore`：默认 10 分。
- `assessmentCriteria`：默认提供操作完成情况、操作规范和数据／现象三项检查要点。教师勾选后填写总分，勾选本身不自动计分。
- `processScoreWeight`：过程分在综合成绩中的百分比，默认 40；报告分占余下的 60%。

牛顿环五步的满分依次为 20、25、35、10、10，总分 100，已配置具体检查要点。其他实验采用默认规则，可按实际教学要求逐步配置。修改既有实验的评分标准前，应先确认当前实验批次已结束；历史成绩目前按照该实验当前配置汇总。

全部计分检查点通过后，过程成绩按 `已得分 / 满分 × 100` 汇总；未评完显示“待评价”，不会当作零分。报告正式批改且过程评价全部完成后显示综合成绩：`过程成绩 × 过程占比 + 报告成绩 × 报告占比`，结束后补评会实时更新汇总。没有过程成绩的历史记录不生成综合成绩。现有报告分字段及学习统计中的历史报告评分口径保持原有含义。

## 数据和验证

教师端“实验评价”提供顶部批量批阅、Excel 成绩导出及全部已提交报告 ZIP 导出。评价名单、批量批阅与导出均限定为当前实验已分配且教师有权限管理的班级；不包含仅有历史记录、但已不再分配当前实验的班级。顶部“去批改”忽略列表中的临时筛选，打开全部符合范围的报告队列；行内入口进入单份批阅，隐藏名单与跨学生切换，返回评价列表后可重新选择学生。ZIP 按班级分目录，使用唯一学生与报告标识避免重名覆盖，电子版报告保持原始内容与格式，在线报告导出为 Word。

报告分析先展示学生成绩列表，列出实际报告提交时间、报告得分、AI 得分及过程考核总分，支持名单搜索、班级与提交状态筛选、成绩与时间排序。未评完的过程总分显示“待评价”，零分正常显示；历史记录无准确提交时间时显示“—”，不以实验结束或最近批改时间代替。列表可进入报告批阅，或打开独立的过程详情页查看各步骤图片、数据表格与得分；过程详情沿用教师班级权限，不依赖当前过程考核教学班选择。

学生实验报告页支持上传 PDF / Word（.docx）电子版报告，单文件不超过 20MB，选择文件后点击“提交文件报告”正式提交。报告需关联本人已结束的对应实验，已提交的文件和已批改的报告不能覆盖。原文件保存在现有文件存储中，教师与本人通过鉴权接口下载；PDF 可在批阅区预览，Word 下载原文件查看。电子版报告的 AI 预评使用上传的原文件，旧在线正文报告仍使用原来的导出预评流程。导出草稿不再自动标记为提交。

新增 `student_experiment_progress.report_submitted_at` 和报告附件元数据列，由现有 Hibernate 更新配置创建。`ReportAttachmentIntegrationTest` 覆盖格式校验、文件原样存取、会话与班级权限、提交时间独立于评分时间、AI 使用原文件、过程总分与详情；前端报告测试覆盖列表排序筛选、零分及上传失败重试。

新增 `step_assessments` 表。当前部署配置使用 Hibernate `ddl-auto: update`，重启后端时自动创建，无需清空旧表。记录带版本号，并通过用户行锁串行化同一学生的过程提交和评分。

新增后端测试 `ProcessAssessmentIntegrationTest` 覆盖禁止跳步、提前结束、数据／问答绕过、跨学生／班级权限、重复提交、退回整改、复查通过、证据快照、过期评分、新对话恢复和成绩计算；`ProcessAssessmentServiceTest` 覆盖无需教师检查的步骤与可配置的成绩比例。测试使用独立的临时 MySQL 数据库，按项目 README 设置测试账号后运行：

```powershell
mvn '-Dtest=ProcessAssessmentIntegrationTest,ProcessAssessmentServiceTest' test
```

学生端的拍刻度按钮、读数助手入口、实验台读数弹窗及自动打开弹窗的链接已移除，AI 工具列表隐藏读数助手。手工填写数据、实验拍照纠错与 CCD 成像继续使用现有流程。
